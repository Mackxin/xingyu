# content/ —— 全站内容就这一个文件

```
content/site.json      ← 全部内容都在这
```

里面五段，改哪段就是改哪块：

| 键 | 管什么 |
|---|---|
| `site` | 站名、标语、配色、首页文案、关于页、赞助位 |
| `nav` | 导航的 50 个分类 / 2081 条链接 |
| `feed` | 「分享」页的时间线，一条一个对象 |
| `posts` | 文章，一篇文章一个对象（`body` 是 Markdown 正文） |
| `entries` | 首页那四张快捷卡片 |

## 平时怎么改

**开后台改，别手改这个文件。**

1. 双击桌面 **「壹号栈 · 本地预览」**（终端窗口别关，它同时管预览和一键发布）
2. 用它给的 `127.0.0.1` 地址进后台（页脚 **⚙︎ 后台管理**）→ 左边「导航 / 分享 / 文章 /
   首页内容 / 主题 / 站点信息」随便改。这个地址下前台直接读草稿，改完切过去就能看
3. 看完满意，回后台 **💾 发布上线 → 🚀 确认内容，直接发布到线上**

第 3 步会把内容写进这里、校验、烘产物、推 GitHub、传国内镜像，最后逐项核对。
网页 / App / 镜像一起新。日志就在按钮下面滚；内容写错当场停手并还原上一版，线上不动。
看不准先点旁边的「🧪 先试跑（不推远端）」。

**不在那台电脑上**：后台 **⬇ 导出 site.json（全站内容）** → 把下载的文件
**拖到桌面「壹号栈 · 拖文件上传」**，效果一样。

> 后台改的东西先是**本机草稿**：前台和线上都还没变，导出了才算交棒。
> 所以「后台改了、网站没变」不是 bug，是还没发布。
>
> **例外：本地预览里前台直接读草稿。** 双击「壹号栈 · 本地预览」，在它打开的地址
> （`127.0.0.1`）上进后台改，切到前台就是最新的，不用导出。左下角会挂一条
> 「草稿预览」说明这还不是线上。线上域名下仍然只读 `site-data.js`。
>
> **覆盖了这个文件，网站也不会变。** 站点运行时读的是烘出来的
> `assets/js/site-data.js`，从来不读 `site.json`。所以覆盖完必须烘一遍 ——
> 双击「本地预览」就是干这个的，它烘完还能顺便让你看看。

## 想手改也行

`site.json` 是标准 JSON，缩进 2 空格。改完：

```bash
node tools/build-content.js --check   # 只校验，报第几行第几列
node tools/build-content.js           # 通过才写 assets/js/site-data.js
python3 tools/preview.py              # 烘一次 + 本机起页面看效果（不碰远端）
```

再加一条分享（粘在 `feed` 数组最前面，**最后一条不要逗号**）：

```json
{ "date": "2026-11-26", "icon": "🧩", "title": "标题",
  "url": "https://example.com", "desc": "一句话说明", "tags": ["工具"] }
```

## 写错了会怎样

构建器会停下并说清楚：

```
✗ content/site.json 里有 1 处写得不对：
  · content/site.json：第 812 行 24 列 附近写错了（Unexpected token）
```

这时候**一个字都不会发出去**，线上还是上一版。

阻断（必须改）：缺 `title` / 日期不是 `2026-11-26` 这种 / id 重复 / 正文是空的。
只提醒（照发）：某条分享没有 `url`（纯文字卡）、同一天同标题出现两次。

## 两句提醒

- `assets/js/site-data.js` 是**产物**，由 `tools/build-content.js` 生成，手改会被覆盖。
- 这个目录**不上传到镜像**（`tools/*.py` 的 SKIP 清单里），它只是源文件。
