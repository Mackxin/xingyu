改个文件，双击一下就上线

内容已经是仓库里的普通文件了 —— 不用开后台、不用导出。改完双击桌面那个图标，网页 / App / 国内镜像一起新。

1先记住一件事

你负责：content/ 里的文件 content/feed.json　加分享 content/posts/*.md　写文章 content/nav.json　改导航
→
电脑负责：其余全部
site-data.js　网页读的（产物） api/app.json　App 读的（产物） app.json.gz / feed.xml　产物

以前那套「后台改 → 导出快照 → 覆盖文件」已经拆掉了。现在内容只有一份： 仓库里那几个文件。改了它们就是改了内容，同步脚本负责把它们烘成上面那些产物。

2三步流程

  1. 改 content/ 里的文件

    加一条分享改 content/feed.json；写文章在 content/posts/ 新建一个 .md。保存就好 —— 不用开后台、不用导出。

    用任何编辑器都行（VS Code、记事本、手机上的 GitHub 网页）。加完就是几个字符的改动，git diff 一眼能看出改了哪一行。

  2. 双击桌面的「壹号栈 · 一键同步」

    它先校验再构建：少个逗号、日期写错，会当场告诉你哪个文件第几行，并且不发布 —— 线上还是上一版，不会白屏。

    构建 site-data.js → 烘 app.json / feed.xml / app.json.gz → 提交推送 → 传国内镜像 → 清 jsDelivr → 核对三端

    桌面上找不到图标：后台「发布上线」里有「📋 复制同步命令」，粘进终端回车，效果一样。

  3. 看最后一句

    出现「全部完成 ✓」就是三端都新了。之后：

    网页　⌘⇧R 强刷一次（或下拉刷新）　·　App　切到后台再回来，或首页下拉

3四个文件各管什么

文件管什么怎么改
content/feed.json「分享」页的时间线一行一条，新的放最上面
content/posts/*.md文章一篇一个文件，开头几行写标题 / 日期
content/nav.json导航分类 + 2081 个站点一个分类一段，每条链接一行
content/site.json站名、首页文案、主题、关于页跟以前后台「站点信息 / 首页内容 / 主题」调的是同一批
外观（站名 / 主题 / 首页文案）可以照旧在后台调 —— 调完只管本机预览。 满意了去「发布上线 → ⬇ 导出 site.json」，把下载到的文件覆盖进 content/site.json，再走第 2 步，就跟改别的文件一样。

加一条分享

打开 content/feed.json，在 [ 后面粘一条。注意最后一条不要逗号，别的都要。

  {"date": "2026-11-26", "icon": "🧩", "title": "标题",
   "url": "https://example.com", "desc": "一句话说明", "tags": ["工具"]},

写一篇文章

在 content/posts/ 新建 我的标题.md。开头那几行（front-matter）写完，下面随便写 Markdown。

---
title: 我的标题
date: 2026-11-26
tags: [工具, 前端]
excerpt: 列表页显示的一句话摘要
---

正文从这里开始，## 标题、- 列表、**加粗**、` 代码 ` 都支持。
date 必须是 2026-11-26 这种格式（斜杠、月日不补零都会被拦下）。 excerpt 不写也行，会自动取正文第一段。

4谁读哪个文件

端读的东西什么时候变新
网页assets/js/site-data.js（从 content/ 烘出来的）推送后 GitHub Pages 重建，约 20 秒 ~ 4 分钟
Appapi/app.json —— 配了镜像就只问镜像镜像传完立刻生效（所以同步脚本那一步不能只做一半）
RSS 阅读器feed.xml同上，同步时自动重烘
App 安装包api/app.apk + app-version.json只有发新版才动，改内容不碰
容易踩的一点：App 是「有镜像就只问镜像」。镜像上那份 app.json 旧了， App 就一直读旧的，不会自动退回 Pages。所以同步要跑完整。

5出问题了看这张表

碰到的样子意思 / 怎么办
✗ content/ 里有 N 处写得不对它会点名文件和行号（少了逗号、多了逗号、日期格式不对）。改完重跑。这次一个字都没发出去，线上没事。
最后一句不是「全部完成 ✓」上面标 ✗ 的那行就是原因；按它写的重跑一次，已经做完的步骤不会重复做。
✗ 推送还是失败网络没通。开代理后再跑一次。这一步失败时镜像会整段跳过，所以必须补跑，否则手机上还是旧内容。
网页新了、App 还是旧先确认镜像地址写的是 http://yihaozhan.xyz/（带 http://），再切后台回来。
某个文件传失败 / 线上 404FTP 连着传会被限流，失败即删文件。隔几分钟重试同一条命令通常一次就过；然后跑一次 python3 tools/verify-ftp.py 全量核对。
本机看着还是旧的老浏览器里存着一份旧内容副本。后台「发布上线 → 其它」里有「🧹 清掉本机旧副本」，点一下再刷新。
只想让网页变、不动镜像终端跑 python3 tools/sync.py --no-ftp。

6命令速查（要动参数时看）

python3 tools/sync.py
常规：构建 content/ → 一条龙推到全端
node tools/build-content.js
只构建（改了内容想先看对不对）；加 --check 只校验不写
… --dry
只说要做什么，不写文件、不提交、不上传
… --no-ftp
只推 GitHub，不动国内镜像
… --all
整站重传镜像（改了代码才用，慢且容易掉文件）
deploy-ftp.py --files a,b
只补传指定文件（一次别超过 3 个）
verify-ftp.py
走 HTTP 逐文件核对镜像，全部 ✓ 才算完

全部自己手动（不跑一键脚本）

一键脚本没有别的魔法，就是下面这几条串起来。想自己一条条跑，照这个顺序，别跳步。

cd "/Volumes/1T宝盘/workbuddy/星屿"

# ① content/ → site-data.js（校验不过会停，不会写出坏文件）
node tools/build-content.js

# ② 重烘三份产物（产物不许手改，只能现烘）
node tools/gen-app-json.js --plain
node tools/gen-feed.js
python3 - <<'PY'
import gzip
raw = open('api/app.json','rb').read()
open('api/app.json.gz','wb').write(gzip.compress(raw, 9, mtime=0))
PY

# ③ 提交 + 推送（content/ 和产物一起）
git add -A && git commit -m "内容同步" && git push

# ④ 传国内镜像（只传变了的这几个）
python3 tools/deploy-ftp.py --files assets/js/site-data.js,api/app.json,api/app.json.gz,feed.xml

# ⑤ 让 jsDelivr 的兜底源立刻失效
curl -s -o /dev/null -A "xingyu-sync" "https://purge.jsdelivr.net/gh/Mackxin/xingyu@main/api/app.json"

# ⑥ 核对：全部 ✓ 才算完
python3 tools/verify-ftp.py
手动比一键少的只有两样：① 自动算出「该传哪些文件」；② 失败后的重试与补传。 其余一模一样。

最容易漏的三处：忘了先跑 build-content（改了 feed.json，网页还是旧的）、 忘了压 app.json.gz（网页是新的、App 还是旧的）、 commit 了没 push（本地全对、线上一字未变）。

什么时候要发版（+1 版本号）：只有改代码才需要 —— 动 app.js / style.css / sw.js 这类文件时，把 index.html 的 ?v=NN 和 sw.js 的 VERSION 一起 +1。只改内容不用动版本号。

7三件别做的事

别手改 assets/js/site-data.js它是产物，下次构建就被覆盖。要改内容，改 content/。
别在后台改内容「站点数据 / 分享 / 文章」三个面板已经下掉了 —— 后台只剩外观。内容在文件里。
别在公共 WiFi 跑 FTP服务器不支持加密连接（TLS 被 534 拒绝），凭据是明文过网的。
